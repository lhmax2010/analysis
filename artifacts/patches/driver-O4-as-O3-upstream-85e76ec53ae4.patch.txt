Subject: [PATCH] [Driver] Treat -O4 as -O3 in clang::getOptimizationLevel (backport)

Backport of upstream llvm-project commit
85e76ec53ae4e5caea5a13b084c19ba4e2f3a6ce (PR #216450, Wael Yehia,
2026-08-17): "[Driver] Treat -O4 as -O3 in clang::getOptimizationLevel,
which is called when building LTO link command". Not in 22.1.8.

Why: LLVM 22 (PR #169762, commit e60a69ab8a9e7) changed
tools::addLTOOptions() to compute -plugin-opt=O<n> with
getOptimizationLevel(). That function does not expect -O4 (a flag
without a value): with assertions clang aborts on
assert(A->getOption().matches(options::OPT_O)), without assertions it
reads the missing value of -O4. So "clang -flto -O4" linked through the
LLVMgold plugin crashes. With Tizen patch 0002 the plugin is passed on
every GNU ld link, so every link with -O4 would hit it (found as
Driver/fsanitize-object-size.c RUN line 14, -fsanitize=object-size -O4
-###, aborting). Upstream treats -O4 as -O3 again, as addLTOOptions did
before PR #169762.

# KantSU2E kernel trace and memory measurements

This updates the unwind step of the [kernel board procedure](../../comms/codex_to_claude/0012f_reply.md). Use approved flashable images, on the same board, with the verified Official rollback USB. Keep the diagnostic sessions separate from performance and memory trials. Thursday's GBS batch performs no board operations.

1. **Select the lane.** Require a qualified K0, the lane's exact image hash, the running GNU build ID from the board's kernel notes and the native folder `jobs/kernel-thumb/symbols/<GNU-build-ID>/<lane>/`. Verify `SHA256SUMS` there. Retain the unstripped vmlinux, System.map, generated config, full build log and trial-image receipt. Record the kernel relocation slide from a verified load address and the link map (or verified absence of relocation). If either identity or slide is unknown, keep the raw addresses and stop interpretation.
2. **Choose one real call site for each lane.** Use the lane’s `static.board_site` in `kernel-matrix.json`. It gives a helper address range, the branch PC and caller, the static call path from a proc show function, and the read-only proc file to read. Verify the edge against the disassembly in `helpers[addr].calls`, and the expected frames against the current lane’s unwinder. For K1 and K3 inspect LR save/restore and caller FP setup. For K5 check the EHABI row covers the sampled PC, its decoded stack/return operations match the helper instructions, and both the caller and any nested callee can unwind. Missing coverage, CANTUNWIND, unsupported bytecodes or a missing origin remain explicit findings. For K0, K2 and K4 use their own site if the baseline has helpers. If a baseline has none, record “no outlined site” and exercise its paired workload as a control. If there are helpers but no uniquely joined, reachable site, inspect the per-caller ledger and agree a specific normal kernel path before the visit. An arbitrary module call or a trace elsewhere cannot qualify that lane.
3. **Trigger and sample.** On an approved diagnostic boot, repeatedly read exactly the proc file the site selector named. For example, a route rooted in `meminfo_proc_show` uses repeated reads of `/proc/meminfo`. A path through an unexecuted conditional block supplies no evidence. Capture kernel PCs and callchains with the board’s supported kernel sampler, for example `perf record -e cpu-clock:k -g` around the reader on that task, then `perf script` locally. Use the reviewed board scratch directory. Check that the sampler returns raw PCs and kernel callchains before the repeated trial. When polling does not reach a short helper, retain the misses; the separate reviewed diagnostic-module or debugger procedure must sample the identified site or its known callee. A public function's name alone does not establish that the outlined path was reached.
4. **Symbolize every trace offline.** Keep each complete oops, WARN, SysRq or sampler trace, plus lane, boot ID and address provenance. The candidate disables KALLSYMS. Run the staged native reader against each trace and retain its JSON alongside the original. The reader verifies the symbol checksums and running build ID before calling `addr2line -f -i -e`. It applies the supplied slide and clears the Thumb state bit. Treat a saved return address separately from an interrupted PC; inspect the preceding instruction in the lane disassembly to identify its call site. For module frames use the exact module's unstripped ELF/build ID and recorded runtime section base (`addr2line -j <section>` with the section-relative offset). Review unparsed formats, addresses outside the image and unresolved frames individually. Offline symbolization does not reconstruct a frame the live unwinder skipped.
5. **Decide the result.** Require a sampled PC in the selected helper or demonstrated callee and the expected symbolized chain into the selected caller, including any legitimate tail edge. Check the raw saved PC/LR, function offset, expected return instruction and parent against the static record. A missing or misattributed parent at a proved hit is a failure. A missed site, unknown module base or missing debug information is inconclusive. Return source file, caller, helper address, lane build ID and raw/symbolized frames. Preserve raw data and restore the Official image via the approved rollback procedure on an unexpected fault. Keep the standard five cold boots, microbenchmarks and media runs in their original measurement sessions.

Native offline invocation, normally seconds per short trace, one core and local disk only. All inputs and outputs are under the native workspace. Use the Thursday-staged script.

```bash
python3 -B "$THU/trace-symbolize.py.txt" "$MATRIX/symbols/$RUNNING_ID/$LANE" "$TRACE" \
  --running-id "$RUNNING_ID" --slide "$VERIFIED_SLIDE" --output "$TRACE.symbols.json"
```

The return packet reader is `python3 -B "$THU/development.py.txt" packet "$TRACE.symbols.json" 1` for traces saved in the Thursday workdir. Its header gives the remaining page count.

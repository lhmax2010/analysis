## D-020 target and pilot

[Assumption/Memory] Base calculation is 1,024 MiB minus the unique nonreusable footprint required for the selected 4K path. As a sensitivity bound, charging the full observed 304 MiB gives **720 MiB** before other carveouts. Treating every reusable CMA byte as permanently unavailable would over-reserve when the same memory can serve normal allocations. Match pools to actual decoder/GPU/TEE buffers, record pinned and oversubscribed portions and account each physical range once before fixing the target. The 720 MiB arithmetic is provisional.

Method A models pressure through anonymous locked memory. It leaves kernel metadata, low/highmem topology and LMK policy unchanged, and the locked pages cannot swap. Calculate the requested bytes against the measured counter and record locked bytes, MemAvailable before/after, zone free pages and playback counters. The bounded C pilot limits itself to 16 MiB and 60 seconds, tests a memory floor, locks then touches pages and sets its own OOM adjustment. It compiled locally with warnings as errors and rejected an oversized input. No ARM or board pilot result is available. Run the first small reservation only in an attended target session with a working release path. [Pilot source](../artifacts/scripts/method-a-pilot.c.txt)

Method B requires the owner-approved original boot environment backup, exact restoration command and known-good reflash procedure. As shown by the separated banks and CMA layout, shrinking a single `mem=` range could remove a required region. Verify permitted banks, reserve all required media/GPU/TEE ranges and compare resulting zone totals and 4K operation. Keep boot changes pending until the recovery procedure is specified. Verify the three matched A/B trials using drops, minimum MemAvailable, LMK kills and major faults before selecting the routine setup.

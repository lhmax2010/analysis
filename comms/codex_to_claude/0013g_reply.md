## KantSU2E board runbook · proposed for the Thumb QB

1. **Freeze the pair and stimuli.** Board QA records the Thumb QB ID, Official 37777148, same physical TV, verified USB manifests, Product VCS diff, Base and kernel build IDs, installed package deltas, and tool/fixture hashes. Record final ISA, optimization and LTO per treatment package. Keep the Official bundle available for rollback. Pre-register the five shipped app IDs, their visible ready events, the actual local 4K stream SHA and timestamp/codec, player launch method, seek target, frame-drop and A/V-sync counters. Validate counters advance on a known test. Record platform build IDs for crash-worker, unwinders, profiler and their symbol packages. An unavailable signed tool, media stream or counter leaves the corresponding metric open.
2. **Visit protocol.** Alternate Official and Thumb on the same board. Counterbalance the first lane across blocks where possible. Verify Product, boot ID, Home focus, kernel ID and test-tool hashes each visit. Keep input source, player state, resolution, volume, network, governor, idle dwell and thermal conditions matched. Treat cold power-to-responsive-Home and process start as separate timestamps. Retain each invocation, exit code, elapsed time, sample count and denominator. Store host readouts under vd-tree, board scratch under the agreed QA directory. Review missing/outlier pairs individually and report their disposition.
3. **P1, hot functions.** Three matched profiles per image for a fixed 4K interval plus a scripted Home/navigation sequence. Use the same permitted signed perf sampler, events, period, capture duration and privileges on both. Retain build IDs, sample counts, lost samples and unresolved PCs. Resolve symbols against the exact image debuginfo, use mapping symbols or verified function mode and give each top function its RPM and sample share. Report which hot functions changed ISA. Keep profiling runs separate from uninstrumented latency trials.
4. **P2, throughput.** Five paired trials per image per workload. For compression reuse the 16 MiB zero input (`080acf35a507ac9849cfcba47dc2ad83e01b75663a516279c8b9d243b719643e`), CPU 0, gzip `-n -6 -c`, xz `-T1 -3 -c`, and a fixed single-thread zstd level (proposed `-T1 -3 -c`). Send compressed bytes to the same sink. Use signed OpenSSL speed SHA-256 and AES-CBC with the same buffer sizes, duration and acceleration configuration. For JPEG/PNG decode fix compressed input hash, output pixel format and dimensions and check decoded checksum. Use a signed in-image memory benchmark with identical memcpy/memset alignment, buffer sizes, byte counts and output validation. Verify all tools and loaded library builds. Calibrate trial length to the timer resolution and apply the same warm-up to each lane. Report five raw pairs and medians. For elapsed time use Thumb/Official − 1; for throughput use 1 − Thumb/Official. Any median regression above 3% goes to package analysis.
5. **P3, system behavior.** Five cold power cycles per image timed to responsive Home. Five cold launches of each of the five preselected apps to its registered ready event. Use the same initial app state and launch order. Three unprofiled runs of the same local 4K stream, each with fixed start, seek, recovery, close and reopen points. Collect process/whole-board CPU, delivered and dropped frames, A/V sync offset and seek/reopen latency. Before candidate testing, use repeat Official trials to set the equivalence margin and pairing unit for each metric. Report paired differences and 95% intervals; the interval must fit the agreed band. With three media pairs, an inconclusive interval stays open. Require zero new dropped-frame events. Flag stalls, black frames and sync errors.
6. **P4, memory.** Three matched samples at idle Home after a five-minute dwell and three at a fixed steady-playback offset per image. Read MemAvailable, sum smaps_rollup PSS for the same media/UI process families and children; record missing PIDs, sample offsets, units and process restarts. Report available bytes gained and PSS bytes saved with raw paired values. An increase in PSS or decrease in available memory beyond the predeclared precision requires investigation.
7. **C4, deliberate crash in a QA process.** Use an owner-approved signed QA program with a symbol file and at least three known noinline frames, a Thumb caller and an interworking boundary. Preserve unwind tables, disable sibling-call optimization for the known chain and verify the marker functions' modes against the installed build ID. On each image collect a normal in-process backtrace and profiler sample. Then have the dedicated QA program call `raise(SIGABRT)` once at the leaf under its normal user. Record PID, crash receipt, signal, build IDs and symbolized frames in order, including the first Thumb and mixed-mode callers; compare with the predeclared chain and source lines. Check the real crash collector and applicable profiler/sanitizer paths. An absent matching signed fixture, missing frame, incorrect register convention, or unresolved expected frame leaves C4 open. Complete this visit outside the stability observation window.
8. **P5, 24 h per image.** Record start/end boot ID, uptime, journal cursor and crash-dump inventory. Repeat the same playback/seek/reopen and five-app cycle on both images. Record each completed cycle, downtime, restarts, SIGILL/SIGBUS/SIGSEGV and other new crash dumps. Require full observation and zero new crashes. Preserve the first failure's image, process, build IDs, timestamp and symbolized trace. Restore the verified Official image through the operator's runbook on failure or at completion.
9. **Decision.** Link each failed gate to the affected function/package and its review owner. Rebuild a reviewed package-specific `-marm` exception and repeat the affected static and board gates.

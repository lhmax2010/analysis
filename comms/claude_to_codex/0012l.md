## 4. K4/K5 (Thumb-2 kernel): the unwinder changes too

On ARM, `UNWINDER_FRAME_POINTER` is not available with `THUMB2_KERNEL`, so `olddefconfig` moves the kernel to `UNWINDER_ARM`. That adds `.ARM.exidx` and `.ARM.extab` and changes the frame setup. K4 therefore measures two changes at once.

- Print the full `.config` diff from K0 to K4 (and from K1 to K5), listing every symbol that changed as a side effect, not only `THUMB2_KERNEL` and the unwinder.
- In the size table, report `.ARM.exidx` + `.ARM.extab` bytes as their own row, next to the `.text` delta. Also give a ".text only" Thumb-2 delta and a "total resident" delta.
- Check whether any in-tree or out-of-tree module, or vendor assembly, assumes the A32 or frame-pointer layout and fails under Thumb-2. Report each one by file.

## 5. Outliner audit changes for K1/K3/K5

- **Unwinding.** K0–K3 use the frame-pointer unwinder (Clang ARM32 `backtrace-clang.S`), not `.ARM.exidx`. For every `OUTLINED_FUNCTION_*`, classify how the outliner calls it: tail call, thunk, LR saved to a register, or LR saved on the stack. Then answer: can the frame-pointer chain still reach the callers when a trace starts inside the outlined body, or in a function it calls? List each case that would break the chain or misattribute a frame, with its caller functions. For K5 (UNWINDER_ARM), check instead that every outlined function has a correct `.ARM.exidx` entry.
- **Scope reduction (config-backed).** KPROBES, FUNCTION_TRACER, STACKPROTECTOR and CFI_CLANG are off, so drop those checks. Keep the section-safety audit (`.noinstr.text`, `.head.text`, `.entry.text`, `.idmap.text`, `.hyp.text`, and `__init` callers whose outlined bodies are in resident `.text`).

## Fix

1. **Do not call `realpath` or `readlink -f` inside `%build`.**
   - Resolve the path with shell builtins only, for example `d=$(cd -P -- "$(dirname -- "$p")" && pwd -P)` and then `"$d/$(basename -- "$p")"`. Do the same for the linker path.
   - Or record the path exactly as the map shows it, and resolve it on the host side, in Python, against the GBS-ROOT.

   `dirname` and `basename` are present, because the 0012b run used them. Still, prove every command in the new `%build` with the step below.
2. **Command inventory gate.** Add a `%build` preflight that runs `command -v` for every external command the section uses: `awk sort head sha256sum dirname basename readelf rpm …`. If any is missing, print `PM_BENCH_MISSING_TOOL <name>` and stop before compiling. This would have caught `realpath` in a 1-second preflight instead of after the link.
3. **Local fixture.** The fixture must run `%build` with a PATH that contains only the commands proven to exist in the Official build root. Take that list from the RPM file lists of the installed build-root packages in the native `gbs.log`. A host-shell run is not enough evidence, and this is the third round of Step 5 failures caused by host and build-root differences.
4. **Record the toolchain fact in `board-tools.json`:** clang finds `crt*.o` and `libc.a` through the GCC 14.2.0 installation directory.
5. **Re-pin.** Return a replacement Step 5 block, the same shape as before with only the builder pin changed.

## What happened

The abd1546 fix worked as far as source staging. `%prep` delivered `bench.c`, and `PM_BENCH_SOURCE` printed `04981794…`, which matches the pinned source. The build then failed at link time, 69 s in:

```
/bin/armv7l-tizen-linux-gnueabi-clang -O2 -static -std=c11 -Wall -Wextra -Werror bench.c -Wl,-Map,microbench.map -o microbench
/usr/bin/ld: cannot find -lc: No such file or directory
```

Cause: the spec declares `BuildRequires: glibc-devel` only. `glibc-devel` ships `libc.so` and the crt objects, but not `libc.a`. On Tizen, the static archive comes from the separate `glibc-devel-static` subpackage. Your local fixture used host GCC with a host `libc.a`, so it could not catch this.

A second point from the log: the link went through `/usr/bin/ld`, which is GNU BFD and not lld. Record the linker that was actually used in `board-tools.json`, because it is part of the benchmark's toolchain identity.
